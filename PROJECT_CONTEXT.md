## Browser buzzing and Reservoir crash correction (2026-09-13)

The user reported very loud buzzing in Night Laundry, Signal Grove and Painted Mere, and Reservoir failing seconds after entry, specifically in this app's local preview. Reproduced the shared cause in the actual exported Web Audio path: those scenes assigned `audio.stream_paused = false` every frame. The shipping engine's sample backend unconditionally restarts a source and duplicates its full AudioBuffer on every unpause. A muted Reservoir probe recorded 2,188 starts, 2,194 buffer allocations and 19,278.8 MiB of cumulative allocation before `createBuffer(2, 1152000, 48000)` began failing. These are cumulative allocations, not a resident-memory reading. The source buffer itself had normal amplitude (peak .175, RMS .0197), agreeing with the original WAV; lowering volume or regenerating the sound would not fix this fault. Reservoir remained stable with sound off.

`scripts/main.gd` now provides `_sync_audio_pause(player)`, which compares the player's actual paused state before invoking the setter. Laundry/Reservoir, Signal, Painted and both Roccella players use it. Reading the live player also handles enabling sound while the scene is already paused. Existing playback types remain unchanged: Roccella retains its streaming setting; the other scenes keep the normal web sample path. The original audio assets, volume levels, scene geometry and effects are unchanged.

`tests/audio_pause.gd`, wired into the full build, checks playback advancement, frozen position during Pause, continuation on Resume, sound enabled during Pause, loop boundaries and Reset for all five affected channels. `tools/serve_audio_probe.mjs` serves a local-only instrumented copy of docs at 127.0.0.1:5186; `tests/web_audio_probe.js` counts real Web Audio source starts/stops and buffer allocations, measures the output, and mutes downstream speaker output.
